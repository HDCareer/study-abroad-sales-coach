# 暂时失联与恢复跟进

规则版本1.0；随留学辅导销售助手 0.7.36提供。公开版由使用机构配置联系政策：曾经聊过的客户后来停止回复，从第一次未获回复的主动跟进起满机构观察时限，期间分开跟进规定次数仍无回应，可转入可恢复的“暂时失联”；已约定晚些联系的客户除外。

本页只补充联系状态。已有有效流量、源销售判断、商机阶段、付费/完课事实、试听按机构时限分档的预警和历史业绩不因此改变。它与[业务事实](business-facts.md#行政线索分类不等于销售判断)中“添加后从未真实回复”的无效失联规则不同，不能互相套用。

## 公开版联系政策

在每案contact_review.policy提供本机构已确认的配置：`{"version":"本机构政策版本","unanswered_hours":<正有限小时数>,"minimum_attempts":<正整数>}`。此处占位不能直接作为JSON执行。policy缺省或null时不补默认值；可见的合理等待、真实回复和未回复轮次仍可核查，但没有机构时限时不新判暂时失联，不计算pause_eligible_at。

结果额外保留policy；`policy_unknown`表示有未获回复的跟进但联系阈值未设。attempt_count与window_end为null、within_window为null时，不把它们当零次或未达门槛。首次主动联系时刻及total_unanswered_attempts仍可展示。来源不齐、等待待核、从未回复和当前无未答序列优先各自表达。旧暂失联缺本次配置时仍按历史待复核保留；不能把撤去配置当作客户已回复。

本页观察时限与独立轮次数仅来自该policy；新客行政失联及试听预警使用各自机构配置，不能合并。政策变更须明确版本并重新复核相关案例。

## 一、怎样判断

必须同时有以下依据，才允许输出暂时失联：

1. 本需求已经有过真实客户回复；通过好友的系统提示不算。文字、图片、语音、文件、链接、表情都算真实回复，内容不可读也不能据此说客户没有回应。
2. 找到本轮第一次未获客户回复的**主动跟进**，以该次起始时刻作为观察窗起点。不是从加好友、客户最后一句话、首次报价或试听完课开始计时。正常回答客户的问题、同一轮回复的补充说明，不自动计为主动追踪。
3. 在从该起点开始的机构规定的观察窗内，有规定次数实际、独立的主动联系。一次连续发出的多条微信合并为同一轮，不能拆开凑次数；AI建议、未发草稿、系统消息和客户消息不算。每轮可以包含多条引用。模型须逐轮说明归组依据，程序不能仅凭消息条数证明是规定次数独立联系。
4. 截至资料截止，距起点已经满机构观察时限，且期间以及之后仍无客户真实回复。不能刚达到规定轮次数就提前判暂失联；观察时限也必须已到。
5. 本轮消息和角色覆盖足够核验；没有仍生效的合理等待约定。缺历史、漏消息、角色不明或约定日期待核时，显示待核，不由AI补猜。

客户说“下周再联系”“等成绩出来”“发薪后付款”等，须保留其依据及下一联系节点。约定尚未到时显示合理等待。节点没有明确时间则先待核，不因为系统计满机构观察时限自动暂失联。约定已到时，只从约定之后新发起的第一轮未获回复跟进计时，不能把约定等待期间的催问倒算进去。

客户在规定次数跟进期间或暂失联之后重新回复，联系状态按新事实恢复；客户仍有合理延迟付款原因的，继续保留在未结/等待清单，明确下一节点，不因尚未付款改成流失。重新失去联系时，重新判断新的跟进轮次，不能沿用上一轮的跟进次数。

## 二、单案输入

在原单案 `management` 中添加可选 `contact_review`；新批次需要本功能时由模型完整阅读原消息后填写，不由页面反推。旧输入可继续使用，缺此字段表示未评定。

```json
{
  "coverage":"complete",
  "policy":null,
  "attempts":[
    {"refs":["本案首次主动跟进消息"],"reason":"本轮主动联系的目的及归组依据"},
    {"refs":["本案第二轮消息一","本案第二轮消息二"],"reason":"这两条属于同一次联系"},
    {"refs":["本案另一轮消息"],"reason":"另一次主动跟进的依据"}
  ],
  "wait":null
}
```

coverage为complete、partial或unknown；complete指本轮跟进到报告截止的消息足够核验，且能核实此前客户回复。不能把“模型声称完整”当作实际API覆盖已验证。attempts可以为空，按真实发生顺序列出所有有关轮次；refs只能指本案实际销售消息，不得重复使用或引用未来。每轮reason不得空；没有“独立联系”的语义依据，不为满足规定次数而拆消息。

有合理等待时，wait为 `{until:<已核实的ISO时刻或null>,reason:<等待依据>,refs:[本案依据消息]}`。until=null表示节点时间待核；不能伪造确切到期。日期和时区使用原报告口径，跨时区未核不直接相减。

程序读取本案完整source_messages，核对引用、角色、顺序、时间、已知客户回复及等待节点。原独立source核验仍然适用，真实原消息不能在contact_review中另写一份替代。程序不判断话术优劣，也不能仅凭reason字段证明模型的轮次归组正确。

## 三、输出与管理动作

标准案例新增 `contact_status`，保留计算截至时点、第一轮起点、机构观察时限窗末、计入轮次数、最近客户回复、引用及原因。缺扩展、资料不齐、从未真实回复、合理等待、仍在观察、新回复恢复、暂时失联分别表达，不用一个真假标记吞掉未知。

status枚举：policy_unknown（机构联系阈值待设）、not_assessed（未评定）、incomplete（资料不齐）、not_applicable（未有真实回复，使用旧新客规则）、waiting（约定未到）、wait_unknown（等待节点待核）、active（当前无未获回复的主动跟进序列）、monitoring（尚未同时满足规则）、temporary_unreachable（暂时失联）、reengaged（客户重新回复）。active只说明联系记录，不等于客户愿意购买或一定成交。

结果字段为status、label、as_of、coverage、first_unanswered_at、window_end、attempt_count、total_unanswered_attempts、attempts、evidence、why、last_customer_reply_at、last_customer_reply_ref、resumed_at、pause_eligible_at、grouping_basis。attempt_count只计算首机构观察时限窗内轮次；total_unanswered_attempts保留当前全部未获回复轮次。attempts记录每轮started_at、ended_at、refs、reason、within_window。未知时间保持null。

主管模块把确定暂失联的普通追单移入可展开的“暂时失联”名单，保留原有效性、原商机、原动作和判断依据；暂失联不写为closed，不删除跨周记录。原已付/完课的课程责任、正式已购后的服务待办，以及明确订单/课程/范围核查仍须保留必要提醒。没有客户回复不能解除这些责任，也不能把试听红色预警直接改成“无须处理”。

只有确有新回复或新的有据评定才更新联系状态。本期完全缺案时保留旧暂失联标签，注明上次核实截止和本期未复核；本期没有contact_review，也不能仅因字段缺失自动恢复或关闭。新的有效回复可以重新进入关注，AI还需继续判断现在的阻碍和下一步，不能把“重新回复”直接算成交。

0.7.37补充：完整评定中新补出的有据等待，即使until=null、输出wait_unknown，也可修正旧暂失联；不要求客户在原暂停之后再发一条消息来证明此前遗漏的约定。必须有完整覆盖、本案引用及本次as_of；修订时contact_refresh_status为revised_from_wait，contact_status.previous_contact保留旧status/as_of/first_unanswered_at/evidence，review_note说明是等待依据修订而非新回复。缺评定或证据不足仍不能恢复。暂停清单展示本期及历史暂停项，并与身份待核并列，不把身份待核当作忽略暂停状态的理由。

旧“无效—用户失联”仍只适用于从未回复的新线索；本页暂失联不会把曾经有效的客户从历史有效流量中删除，不重算过去周/月分母。实际正式购买仍按付款所属周及经营月计业绩。

团队输出在cases及opportunity_pool.entries中新增contact_status、contact_refresh_status、contact_routing（paused、protected、reason）；paused_contact保留本期暂停普通追单的完整行，history_followup.temporary_unreachable保留相应pool_id。decision_log与source_must_follow亦保留contact_routing。若继承旧状态而未有充分更新，保留原as_of并在review_note中说明待复核，不以本期运行时间改成新判断。已付等保护只保留原已选入的管理/顾问事项，不把源attention=none的客户擅自升级为主管介入。

## 四、数据部门接入

沿用原消息、单案交付、prepare/build/verify及previous-team-delivery流程。新增contact_review随单案分析进入，contact_status随统一结果输出；不增加另一套订单或商机终态。完整聊天只有更新消息也不够，必须带本轮必要前史、上一条联系状态和合理等待依据。

需要区别三类独立时钟：从未回复的新线索行政分类、试听完课后转正预警、本页已沟通过后暂失联。数据部门不得合并成一个通用“到时未成交即流失”定时器。

验收包括：尚未满机构观察时限、有多条但同一轮、规定轮次中途收到回复、只有附件回复、规定轮次未落在观察窗内、等待尚未到/时间未知、从未回复的新客、缺角色/缺历史、客户再次回复、旧快照未更新、已付课程责任仍保留。结构通过不代表轮次语义判断或实际模型覆盖已获人工认可。
