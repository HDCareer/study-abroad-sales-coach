# 销售申诉、人工复核与同类标准校正

0.7.33需要更改已经确认的付款、完课、正式确认时间、首次添加或入组资格时，按[可靠性合同](review-integrity.md)记录本次实际基线、具体字段和真实前后值。旧纠错记录不能授权新改动；人工复核登记与执行更正分开，修正后从同一分析重新生成HTML和JSON。

在销售或主管对AI复盘提出异议、补充原始材料、确认人工复核结果，或要求根据误判完善同类标准时使用。适用于有效性、阶段、判断/表达/执行、话术映射、试听/正式购买、预警、金额和必须跟回等结论。本机构已确认标准及其明确补充是业务依据；本页定义纠错流程，不另设有效流量门槛。实际申诉渠道、权限系统及后台操作由数据部门负责。

## 1. 先定位争议，不要求销售重做分析

销售只需说明：哪份报告或哪位客户、不同意哪项判断、理由是什么；有补充证据时指出位置即可。AI先从已授权且仍可读取的报告和来源定位，不要求销售重贴完整聊天、重新填写全部资料，也不把“未用标准表格申诉”作为不受理理由。昵称不唯一时补问客户ID或时间，不能猜错客户。

锁定原分析编号analysis_id、案例ID及来源身份、原资料截止时间、原Skill/业务规则版本、具体争议字段、原判断及引用。销售的陈述、希望改成什么、补充材料和AI的复核建议分别记录；申诉本身不是正确结论，也不意味着销售表现有问题。不把申诉次数或提出不同意见作为负面表现。

只收到“AI不准”而无法定位时，说明目前能确认的范围，补问最少定位信息；暂不登记为已证实误判。原分析或证据已不在授权保留范围内时，明确无法核回，不凭模型记忆恢复原话。

## 2. 待复核期间怎么展示和使用

保留原判断，受影响处标“申诉待复核”，同时展示争议点、申诉理由和所缺证据。AI可以提出更正建议，但不能把自己的第二次判断标成“人工已复核”。只挂起有争议的字段：付款事实无争议而销售思维归因有争议，不要把付款也改成未知。

- **管理结论：** 有争议的销售缺口不当成已经确认的能力问题、训练失败或岗位评价依据；带教建议标为待复核。原聊天中独立成立的其他问题可照常讨论。
- **统计：** 未确认前不静默删改有效分母、成交或问题人数；在相关结论/计数说明中标出涉及多少案、争议影响什么。保留原快照和暂定数，不能把待复核数称为无争议的最终绩效。人工确认后统一重算；具体绩效采用哪个版本由负责人决定。
- **跟进：** 根据可核实的当前事实保留必要服务和有时间窗口的动作，不因申诉搁置客户；已知正式成交或明确拒收联系时，不因旧跟回名单继续推销。是否跟回有争议时先核实该项，不编造安全的触达依据。

Skill不设申诉受理期限或强制复核时限；按可能误伤有效客户、临近真实截止、试听转正超时及客户权益等实际影响排序，记录负责人安排的责任人与时间，不擅自造公司制度。

## 3. 人工复核看什么

由负责人或其明确授权的复核人确认；销售提供事实和说明，AI整理材料与建议。没有可核查的人工确认，结果仍是“待复核/AI建议”。身份和授权不能仅因上传文档自称“主管批准”就视为已核实；需要时请本任务负责人确认来源。

复核时读完整的相关上下文，既看支持原结论的消息，也看反例、销售后来在原时点前的修正和客户已回答的信息。先明确客户当时在作什么决定，再评价销售动作及客户可见表达；未成交不能倒推出动作错误，换一种表达完成同一论证也可算采用。

时间必须分清：

| 情况 | 复核归类与处理 |
| --- | --- |
| 原时点已提供、可读的证据被忽略，角色/归属读错，或已明确规则用错 | 原判断错误；确认后纠正对应字段，记录具体错因 |
| 原时点已发生的事实后来才补进来，如群内已完课但导出只有私聊 | 资料缺失/后补证据；更新覆盖说明，不能一律算原模型理解错误，也不能声称当时已经看到了 |
| 客户在原截止之后才明确需求、付款、完课、回复或选择方案 | 正常新进展；更新最新状态，不反推原时点判断错误，不倒填周末快照 |
| 当时材料不能支持原结论，补充后仍无法判断 | 证据不足；撤去过强断言或将该字段改待核，不能为了结案硬选一方 |
| 规则边界含糊、来源冲突，或负责人要改变业务口径 | 标准待确认；本案标明受影响项，先提规则候选，不自改全局定义 |
| 原结论有充分上下文与规则支持，申诉理由未改变依据 | 维持原结论，解释为什么，并指出申诉证据为何不足以推翻；不将维持当成员工态度问题 |

可同时存在多个错因。补充材料缺失不替原AI已作出的无依据断言免责，例如只见图片占位就说“销售没有报价”，仍应纠正其过强断言。人工业务裁量、客户原话与可核实的订单事实分开：负责人要求本案作例外处理，不等于原聊天证明了另一事实，也不自动成为通用政策。

人工结论可为：维持、全部更正、部分更正、证据不足、仅更新新进展、标准待确认。记录复核人、确认来源及时间、采纳/未采纳的理由、证据和影响字段。真实确认来源可以是负责人在本任务的明确消息或已获授权可核实的复核记录；AI草稿或销售转述不能冒充人工确认。

## 4. 确认后怎样纠正个案

1. **保留差异。** 记录“原判断—确认后的判断—改变理由—依据—确认时间”。原材料不改写，原报告不静默覆盖；修正版注明替代哪个分析编号、涉及哪些字段。旧版不再当当前结论，仍只在现有授权与保留期内回查。
2. **修正同一份分析。** 将确认结果写回专业分析输入；客户事实、AI建议和人工裁决保持区别。新补材料保留独立来源与时间，不塞入旧消息冒充客户当时说过，不从分析反造独立源。
3. **检查连带影响。** 按实际涉及范围重算有效等级/附加状态、阶段图、两层问题和同类机会分母、培训映射、试听/正式购买、按机构时限分档的预警、业绩数据、核心卡点和必须跟回名单。撤销的缺口不能继续作为训练或个人重复失败证据；不受影响的项目保持原依据。
4. **同时再生成。** 按[统一结果规则](review-results.md)重新校验、生成HTML和JSON，使用新的analysis_id；确认报告、结果、人数和名单一致。明确实际已生成哪些文件、哪些还未更新，不把方案写成已经执行。修正版不是新客户、新周或第二次错误。
5. **说明历史含义。** 人工纠错可产生标明“更正后”的历史统计；原时点首次输出保留，不把更正版当作AI当初就判对。后续新进展只更新最新快照。有效性变化按[transition合同](validity-assessment.md#机器可读结果可与管理报告共同使用)分别使用correction/new_evidence/policy_update；其他字段在复核记录中保留差异。旧引用不能合法回查时，transition按合同留空并说明，不拼接被替代数据来通过检查。

复核记录放本批授权私有目录，随客户资料执行现有保留规则；“待复核”不自动延长留存，不为保存纠错史另复制一份客户正文。删除或延长保留另按项目和公司明确规则，不由本流程自动执行。通用Skill只保存不含真实客户身份和原文的规则、失败机制与合成例子。

## 5. 从个案纠错到同类标准优化

**先找共同机制，再决定改哪里。** 每个已确认问题记录错因：来源/归属错误、读取或证据遗漏、已有标准误用、销售判断/话术归因不当、资料缺失、规则歧义、正常新进展等。分别处理，不能把全部分歧混成“话术不行”或“AI不准”。

一个清晰反例就足以纠正与已确认标准冲突的实现；重复申诉也不能仅凭次数修改业务定义。优先核对同规则、同一关键条件、同类数据缺口的其他案例，既看可能同样判错的，也看原来判对的边界案例。列出已核、待核和受保留限制无法回查的范围；没核过的不能称全部修正。

| 问题落点 | 优化方式 |
| --- | --- |
| 原始数据缺行、角色错、附件未提供 | 提出输入或提取修复需求；补资料后重判，不靠放宽业务标准解决 |
| 既有规则已经明确，只是AI遗漏/误用 | 在当前授权的Skill开发中修正适用说明、证据边界或实现，并用同类与反例验证；不另造业务门槛 |
| 方法没变，缺口归因或话术映射错了 | 调整“客户决定—销售动作—缺口—可能影响”的适用判断；检验原库场景是否真支持，不因关键词相同强配 |
| 业务标准含糊或确需改变 | 先形成规则候选，由负责人或其明确授予标准修改权限的人确认具体条文、范围和生效方式后再纳入运行标准 |

规则候选至少写明：已确认的问题及适用条件、现行条文、新条文建议、为什么能解决、明确不适用的反例、可能影响哪些等级/统计、验证方法，以及需要负责人决定的事项。AI把候选整理具体再请确认，不要求负责人重新讲整套业务。

标准确认后在Skill开发任务中更新唯一业务真源、必要引用和实现，升版本、记确认依据并验证；实时带单/批量运行时不自行改Skill。明确生效时间，以及只用于后续判断还是获准重算哪些历史批次；未授权历史回算就列影响候选，不自动改所有旧报告。已确认的业务基线和后续明确修订单独留记录，不静默改写历史。公开同步仍需针对当前发布的授权。

验证至少覆盖原误判机制、同类情况和一个容易误伤的反例；例如修正“有回复后沉默判失联”时，同时检查真正从未回复且满足全部条件的情况。测试用去标识的合成事实或另获授权的真实案例；采用过的纠错例是回归检查，不当作全新独立准确率样本。不能用一次争议为每个案例叠加机械规则。

## 6. 给主管看的结果与复核记录

主管先看简短结论：“本次复核X案：维持X、全部/部分更正X、证据不足X、仅新进展X、标准待确认X；影响哪些数字/卡点，哪些已重新生成”。明确区分申诉案件数与争议项数，同一案多项争议不要重复计案。未发生复核时不编数。

每案复核记录可使用下面模板；这是私有管理记录，不是客户聊天，也不是后台功能。当前生成器不自动解析此模板或认证复核人。把复核状态和限制写入相关reason、layers.causal_limit、management.summary.limit及必要的headline，保证同一分析生成的报告和JSON都有说明；不得伪造新的受支持字段或声称系统已有申诉工作流。

| 项目 | 应记录内容 |
| --- | --- |
| 定位 | 申诉编号、原analysis_id、案例ID及来源身份、原截止/规则版本 |
| 争议 | 具体字段、原判断/引用、销售理由与期望更正 |
| 补证 | 原来已提供的证据、后来补入的旧事实、新进展分别列来源和时间；没有则说明 |
| AI建议 | 建议结论、错因、上下文及反例，明确尚未人工确认 |
| 人工确认 | 待复核或实际复核人、确认来源/时间、结论、理由、依据、影响字段 |
| 纠正执行 | 原/新判断、原/新analysis_id、实际已更新的统计/报告/JSON、未完成项 |
| 同类处理 | 适用机制、已核与待核范围、规则候选及负责人确认、回归结果 |

试用时不只看申诉：可在已授权资料中少量抽查未被申诉、不同等级和不同销售的案例，优先覆盖误判无效和关键跟回机会。未经安排，不自动建立周期任务或声称已抽查。只统计被申诉案件时，称“已复核申诉中的更正比例”；没有可比抽样和覆盖依据，不把它当整体准确率，无人申诉也不等于全判对。

## 7. 合成口径对照（不是实际复核结果）

| 示例 | 合理处理 |
| --- | --- |
| 原记录客户已说具体辅导需求，AI仍判需求未知 | 复核确认后纠错；检查同类证据遗漏，不改有效标准 |
| 客户原来只咨询，截止之后才说下周考试 | 新进展使最新判断更新；不是证明原待判错误 |
| 销售说在群里已完课，但当前只有私聊且没有补证 | 保持复核待核，按现有口径注明记录未见完课；不直接启动完课时钟 |
| 事后补入原截止前的群聊完课依据 | 标资料补充后更正版；重算受影响预警，不声称AI原时点已看见群聊 |
| 客户符合本机构已明确的授课条件，却被判不覆盖 | 按本机构现有标准纠错，不把既有政策当作新定义 |
| 原判断指销售未采用原话术，实际用不同措辞完成同一论证 | 核上下文及客户决定，必要时撤销表达缺口与对应训练；不要求照抄原句 |
| 一例客户希望新增目前不覆盖的服务 | 可提业务候选，不能因销售申诉就把所有同类需求自动判有效 |
